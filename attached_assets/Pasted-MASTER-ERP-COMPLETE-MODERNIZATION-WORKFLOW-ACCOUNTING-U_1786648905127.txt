MASTER ERP COMPLETE MODERNIZATION, WORKFLOW, ACCOUNTING, UI/UX AND VALIDATION PROMPT

IMPORTANT:
This is an existing production ERP.

Do NOT blindly rewrite existing modules.

First inspect the complete existing application, database schema, backend services, APIs, frontend routes, accounting engine, inventory engine, permissions, migrations, reports and existing tests.

The existing ERP functionality is the baseline.

The objective is to improve, simplify and correct the ERP without breaking anything that already works.

============================================================
0. NON-NEGOTIABLE ERP PRINCIPLES
============================================================

1. Accounting must have ONE source of truth.

Every transaction must create the correct accounting/ledger entry.

No report may independently calculate a balance differently from the ledger.

2. Every financial transaction must flow through the correct ledger.

Sale
→ Customer / Cash / Bank
→ Sales income
→ GST
→ Stock

Purchase
→ Vendor / Cash / Bank
→ Purchase / Stock
→ GST

Receipt Voucher
→ Cash/Bank
→ Correct party/account

Payment Voucher
→ Cash/Bank
→ Correct party/account

Journal
→ Correct debit/credit ledgers

Payroll
→ Salary Expense
→ Salary Payable
→ Employee-specific accounting

3. Reports must be generated from the same underlying accounting source.

Trial Balance
Balance Sheet
P&L
Ledger
Customer balances
Vendor balances
Receivables
Payables
Dashboard
Cash Book
Bank Book
Day Book
GST reports

must reconcile.

4. Never create a frontend-only balance.

5. Never duplicate accounting logic in multiple modules.

6. Do not silently change historical accounting data.

7. Any migration must be:
- backed up
- tested
- reversible where practical
- audited
- reconciled after completion

8. Existing month-locking must remain protected.

A locked month must not be modified unless an authorized Admin explicitly reopens it.

9. Existing GST logic must remain correct.

10. Existing permissions must remain enforced at backend level, not just hidden in UI.
