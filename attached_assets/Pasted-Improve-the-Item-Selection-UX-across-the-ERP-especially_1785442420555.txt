Improve the Item Selection UX across the ERP, especially the Point of Sale item selector.

IMPORTANT:
- Development only.
- Do NOT publish automatically.
- Do NOT modify existing production/live data.
- Do NOT create sales, purchases, transfers, stock entries, journal entries, or other business transactions for testing.
- Do NOT change existing accounting, stock valuation, GST calculation, MRP, batch, FEFO, RBAC, warehouse/outlet scope, or business logic unless required to correct an existing defect directly related to this selector.
- This task is primarily a frontend UX improvement, with backend verification for security and location scope.

==================================================
CURRENT PROBLEM
==================================================

Item Master now contains many items.

Item-selection dropdowns are becoming difficult to use in:

1. Point of Sale / Sales
2. Purchase Bill
3. Stock Transfer
4. Any other ERP screen that uses the same Item Master item-selection pattern

The Point of Sale dropdown is especially difficult to read.

Currently rows look approximately like:

Marlin Tender 1.5 kg — 17 avail · MRP ₹380 · 5% GST

When many items are listed, Item Name, Available Stock, MRP and GST are concatenated into one long line.

This is visually messy and difficult to scan quickly during billing.

Replace this with a structured searchable, scrollable table-style item picker.

==================================================
1. CREATE/REUSE ONE SEARCHABLE ITEM SELECTOR
==================================================

Create or refactor a reusable component such as:

SearchableItemSelect

or use the project's existing combobox/searchable-select implementation if appropriate.

Do NOT create three unrelated implementations if the same component can safely serve Sales, Purchase and Stock Transfer.

The component should support configuration for:

- Item name
- SKU/item code
- HSN
- available quantity
- UOM
- MRP
- GST %
- location
- selected item
- disabled state
- search
- permission-sensitive fields
- context-specific columns

Different screens may show different columns.

==================================================
2. SEARCH FIELD
==================================================

Every long Item Master selector must have a search field at the top.

Placeholder:

Search item...

Search immediately while typing.

Do not require Enter.

Search should be case-insensitive and support partial matches.

Where the data exists, search by:

- Item Name
- SKU / Item Code
- HSN

Example:

Typing:

tender

should return:

Marlin Tender
Marlin Tender 1.5 kg
Marlin Tender 500 gm

Typing:

straw

should return:

Strawberry
Strawberry IMO FRT

Provide a clear:

No items found

state when nothing matches.

==================================================
3. SCROLLABLE RESULTS
==================================================

Do NOT allow the item dropdown to grow vertically with the complete Item Master.

Give the results panel a sensible maximum height.

For example, enough for approximately 6–10 item rows depending on screen size.

When additional items exist:

- keep the dropdown height fixed/max-height
- show an internal vertical scrollbar
- keep the search field easily accessible
- do not make the entire page scroll because the dropdown is open

The component must also work correctly on smaller laptop screens and mobile/tablet layouts.

==================================================
4. POS / SALES — TABLE-STYLE ITEM PICKER
==================================================

This is particularly important.

The current POS selector concatenates:

Item Name
Available Qty
MRP
GST

into a single long text line.

REMOVE that presentation.

Make the POS dropdown look like a compact mini table.

Desktop example:

| Item | Available | MRP | GST |
|------|-----------|-----|-----|
| Marlin Tender | 59 kg | ₹395 | 5% |
| Marlin Tender 1.5 kg | 17 kg | ₹380 | 5% |
| Marlin Tender 500 gm | 66 kg | ₹125 | 5% |
| Strawberry | 8 kg | ₹200 | 5% |

Use proper aligned columns.

Suggested structure:

ITEM                         AVAILABLE     MRP       GST
Marlin Tender                59 kg         ₹395      5%
Marlin Tender 1.5 kg         17 kg         ₹380      5%
Marlin Tender 500 gm         66 kg         ₹125      5%

The exact widths can adapt responsively, but the information must remain visually separated.

Do NOT produce:

Marlin Tender 1.5 kg — 17 avail · MRP ₹380 · 5% GST

as one dense line.

==================================================
5. POS TABLE HEADER
==================================================

When the dropdown opens, show a small header row:

Item | Available | MRP | GST

The header should align with the item rows.

If practical, keep the header visible/sticky while scrolling through the results.

The search field should appear above the header.

Desired structure:

[ Search item...                         ]

ITEM                  AVAILABLE     MRP       GST
-------------------------------------------------
Marlin Tender          59 kg         ₹395      5%
Marlin Tender 1.5 kg   17 kg         ₹380      5%
Marlin Tender 500 gm   66 kg         ₹125      5%
Strawberry              8 kg         ₹200      5%
...

Internal scrollbar →

==================================================
6. POS ROW DESIGN
==================================================

Each item must occupy its own clean row.

Requirements:

- Item Name gets the largest column.
- Available quantity is aligned consistently.
- Always show UOM with availability where available.
- MRP should be formatted as Indian currency.
- GST should be displayed clearly as a percentage.
- Use consistent spacing.
- Avoid wrapping ordinary item names unnecessarily.
- Long item names may truncate with ellipsis if required.
- If practical, show the full item name via tooltip/title on hover.
- Selected/hovered row should be visually obvious.
- Do not use excessive colors.

Example selected row:

✓ Marlin Tender 1.5 kg     17 kg     ₹380     5%

The existing application's visual theme should be preserved.

==================================================
7. RESPONSIVE POS BEHAVIOUR
==================================================

On desktop/tablet, use the table layout.

On very narrow/mobile screens, if four full columns cannot fit cleanly, use a structured two-line row rather than returning to one messy concatenated sentence.

Example mobile presentation:

Marlin Tender 1.5 kg
Available: 17 kg   |   MRP: ₹380   |   GST: 5%

The information must remain clearly separated.

==================================================
8. POS STOCK AVAILABILITY
==================================================

The Available column must represent the actual sellable stock for the currently selected/authorized location.

Do not accidentally display company-wide stock when POS is operating against a warehouse/outlet.

Preserve existing:

- warehouse/outlet scope
- reserved quantity handling
- available quantity logic
- batch logic
- FEFO behaviour
- negative/insufficient-stock prevention

Backend stock validation remains authoritative.

Do not trust the displayed number alone when saving a sale.

==================================================
9. POS COST/VALUE SECURITY
==================================================

The POS selector may display:

- Item Name
- Available Qty
- MRP
- GST

It must NOT expose:

- purchase rate
- cost price
- stock valuation
- margin
- profit

unless the employee already has explicit authorization for such information.

Do not weaken the existing stock-value/cost visibility restrictions.
