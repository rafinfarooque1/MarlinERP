Implement a GLOBAL LOCATION CONTEXT for the entire ERP.

This is an ERP-wide architectural enhancement. Do not implement page-specific filters. Implement one centralized Location Context that every module, API, SQL query, report, and dashboard consumes.

=========================================================
OBJECTIVE
=========================================================

Add a permanent Location Selector at the bottom-left corner of the ERP sidebar.

Example:

📍 Current Location

▼ All Locations

or

▼ Ragiguda Warehouse

or

▼ QA Warehouse

or

▼ Head Office

The selected location becomes the active working location for the entire ERP.

=========================================================
DEFAULT BEHAVIOUR
=========================================================

Default after login:

All Locations

If the user changes to another location:

Example:

QA Warehouse

remember the selection.

After refresh or logout/login, the selected location should remain until changed.

Store the preference in the backend (preferred) or user settings, with local storage only as UI cache.

=========================================================
GLOBAL BEHAVIOUR
=========================================================

Changing the location should immediately refresh the entire ERP.

Every module must automatically use the selected location.

No page should implement its own location logic.

Create one reusable Global Location Context used by frontend and backend.

=========================================================
TRANSACTION FILTERING
=========================================================

When "All Locations" is selected:

Show consolidated ERP data.

When a location is selected:

Show ONLY transactions belonging to that location.

Example:

Selected:

QA Warehouse

Only show:

QA Warehouse Sales

QA Warehouse Purchases

QA Warehouse Expenses

QA Warehouse Inventory

QA Warehouse Cash

QA Warehouse Bank

QA Warehouse Payroll

QA Warehouse Rent

QA Warehouse Receivables

QA Warehouse Payables

QA Warehouse Profit

QA Warehouse Stock

Nothing from any other warehouse should appear.

=========================================================

=========================================================

Chart of Accounts

Trial Balance

Balance Sheet

=========================================================
DATE FILTER COMPATIBILITY
=========================================================

Location filtering must work together with Date Filtering.

Example:

Date:
01-Aug-2026 to 31-Aug-2026

Location:
QA Warehouse

Only August transactions belonging to QA Warehouse should be shown.

Never show transactions from another location.

=========================================================
PERMISSIONS
=========================================================

Users should only see locations they have access to.

Examples:

Head Office
→ Can switch between all locations.

Warehouse Manager
→ Only their warehouse.

Outlet User
→ Only their outlet.

If the user has only one location assigned:

Hide the selector and automatically use that location.

=========================================================
BACKEND IMPLEMENTATION
=========================================================

Do NOT filter data in React.

Filtering must happen in backend queries.

Create one reusable location middleware/service.

Every API should automatically receive the active location.

Use:

location_id

and

location_type

where required.

When "All Locations" is selected, do not apply location filtering.
