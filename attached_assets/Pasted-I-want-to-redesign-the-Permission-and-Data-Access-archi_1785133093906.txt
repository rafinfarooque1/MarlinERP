I want to redesign the Permission and Data Access architecture to follow a professional ERP standard.

The current implementation has several problems.

1. Some modules do not appear in the sidebar even though View permission is enabled (example: HR).
2. Cash Balance appears in multiple places and should have only one permission.
3. Permissions and data filtering are mixed together.
4. Users can receive module permission, but branch-level data visibility is not consistently enforced.

I want a professional Role-Based Access Control (RBAC) + Branch Data Access architecture.

==================================================
PERMISSION RULES
==================================================

Permissions determine ONLY whether a user can access a page.

Branch assignment determines WHICH DATA is visible.

Never mix these two concepts.

Example:

Permission = HR View
Branch = Warehouse Bangalore

Result:

User can open HR pages.
User can only see employees belonging to Warehouse Bangalore (or whatever business rules allow).

==================================================
SIDEBAR RULE
==================================================

If View permission is ON

→ Show the module in the sidebar.

If View permission is OFF

→ Hide the module completely.

This rule must work for every module.

Current issue:

HR permission is ON but HR does not appear.

Investigate and fix the root cause.
