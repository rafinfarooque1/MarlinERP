Fix purchase-edit → stock-batch synchronization.

CURRENT BUG

A purchase was created with an incorrect MFG/expiry date.

I later edited the Purchase Bill, corrected the MFG/expiry date, and saved it successfully.

The Purchase Bill now shows the corrected dates, BUT:

Operations → Stock / Live Stock still shows the item as "Expired batch".

This indicates that editing a purchase updates the purchase line but does NOT correctly update the corresponding stock batch / inventory record.

This must be fixed at the backend/data level, not by hiding the "Expired batch" warning.

1. TRACE THE CURRENT DATA FLOW
==================================================

Inspect exactly how a Purchase Bill creates inventory.

Trace:

Purchase Bill
→ purchase line
→ stock entry / stock ledger
→ stock batch
→ MFG date
→ expiry date
→ available stock
→ Live Stock status

Then inspect the Purchase Bill EDIT/UPDATE flow.

Determine why the edited:

- batch number
- MFG date

are saved on the purchase but not reflected in the inventory batch used by Live Stock.

==================================================
2. REQUIRED BEHAVIOUR
==================================================

When an existing Purchase Bill is edited and saved, all inventory records created by that purchase must remain synchronized with the purchase.

For each purchase line, if these fields are changed:

- batch number
- manufacturing date
- expiry date

update the corresponding stock batch created by THAT purchase line.

Example:

Original purchase:

Item: Anjir OF
Batch: PUR-xxxxx
MFG: 21-04-2026
Expiry: incorrect date

User edits purchase and changes expiry to:

21-04-2028

After Save Purchase Bill:

Purchase line expiry = 21-04-2028
Stock batch expiry = 21-04-2028
Live Stock expiry = 21-04-2028

The "Expired batch" warning must disappear automatically if the corrected expiry date is in the future.

Do NOT require a second manual stock edit.

==================================================
3. USE RECORD RELATIONSHIPS — NOT ITEM NAME
==================================================

Very important:

Do NOT update batches by item name alone.

A single item can have:

- multiple purchases
- multiple batches
- multiple MFG dates
- multiple expiry dates
- multiple warehouses

The update must target ONLY the stock batch/stock entry originating from the edited purchase line.

Use the existing relationship such as:

purchase_id
purchase_line_id
stock_entry_id
batch_id

or the project's equivalent authoritative relationship.

If that relationship is currently missing, investigate the safest deterministic way to establish it.

Do NOT update unrelated historical batches.
