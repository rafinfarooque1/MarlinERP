MOBILE ERP APP EXPANSION — USE EXISTING EMPLOYEE APP AS THE MASTER UI

IMPORTANT:

There is already a working mobile app for this ERP.

The current app is mainly an Employee Portal containing:

- Home
- Payslips
- Attendance
- Leaves
- Check In / Check Out
- Employee information

I have provided the current app screen recording.

DO NOT throw away the existing mobile app.

DO NOT redesign it from scratch.

Use the CURRENT MOBILE APP as the master visual/design reference and expand it into a proper ERP mobile application.

The current app already has a good modern mobile UI:
- dark professional theme
- rounded cards
- bottom navigation
- large touch-friendly controls
- clean typography
- colored status indicators
- compact dashboard cards
- mobile-first layout

KEEP THIS DESIGN LANGUAGE.

The objective is to add ERP operational functionality while preserving the existing Employee Portal functionality.

============================================================
4. LOCATION RULES
============================================================

Follow the exact ERP location permission model.

WAREHOUSE EMPLOYEE:

Can see only their assigned warehouse.

OUTLET EMPLOYEE:

Can see only their assigned outlet.

HEAD OFFICE EMPLOYEE:

Current Location selector may contain:

- Head Office
- permitted warehouses/outlets
- All Locations

All Locations:

→ consolidated data

Head Office:

→ Head Office data ONLY

Warehouse:

→ that warehouse ONLY

IMPORTANT:

Never allow a warehouse employee to access another warehouse by changing:

URL
API parameter
location ID
request payload
mobile route

Location security must be enforced by backend APIs.

39. IMPLEMENTATION SAFETY
============================================================

Before making changes:

1. Inspect the existing mobile app.
2. Inspect the existing ERP backend APIs.
3. Inspect authentication.
4. Inspect permissions.
5. Inspect location restrictions.
6. Identify which APIs can be reused.
7. Do not duplicate existing backend logic.
8. Create a checkpoint before major changes.

Implement incrementally.

Do not break the existing employee app.
