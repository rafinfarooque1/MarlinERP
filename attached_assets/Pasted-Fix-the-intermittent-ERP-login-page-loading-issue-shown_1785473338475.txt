Fix the intermittent ERP login/page-loading issue shown in the attached screenshot.

SYMPTOM:
Sometimes after opening the ERP or logging in, the application shell loads successfully:
- sidebar/header appear
- user avatar appears
- navigation layout appears

But the main page remains stuck showing skeleton/loading placeholders indefinitely.

If I log out and log in again, the problem usually disappears and the ERP works normally.

This is intermittent, so DO NOT apply a cosmetic workaround or simply increase loading timeouts.

==================================================
1. INVESTIGATE ROOT CAUSE
==================================================

Trace the complete application startup flow:

Login
→ token/session creation
→ session restoration
→ current-user fetch
→ employee/user profile
→ role
→ permissions
→ warehouse/location scope
→ company context
→ frontend auth context
→ protected routes
→ page API requests
→ loading-state completion

Look specifically for race conditions where protected page queries execute before authentication,
permissions, employee scope, location scope, or company context has finished initializing.

==================================================
2. CHECK SESSION RESTORATION
==================================================

The application must work correctly in ALL of these cases:

- fresh login
- browser refresh
- reopening an existing logged-in tab
- opening ERP in a new tab
- session restored from stored credentials/token
- navigation directly to a protected URL
- temporary slow API response

A restored session must initialize exactly as reliably as a fresh login.

Do not require logout/login to repair application state.

==================================================
3. LOADING STATE MUST ALWAYS TERMINATE
==================================================

Audit every loading/skeleton condition involved in application startup.

There must be no code path such as:

loading = true
→ request fails / auth not ready / permission request skipped
→ loading never becomes false

Every request must end in one of:

SUCCESS
ERROR
UNAUTHORIZED
FORBIDDEN
SESSION EXPIRED
RETRYABLE NETWORK ERROR

Never infinite skeleton loading.

Use try/catch/finally or the equivalent query-state handling so loading state always resolves.

==================================================

If pages depend on:

currentUser
employee
role
permissions
location
warehouse
company

For example:

restore session
        ↓
validate authentication
        ↓

        ↓

        ↓

        ↓
mark auth context READY
        ↓

Do not let individual pages guess whether authentication has finished.

5. TOKEN / SESSION FAILURE
==================================================

- access-token expiry

A. refresh/re-establish the session safely, if supported

B. clearly return the user to login.

==================================================

This issue is intermittent, so specifically test for race conditions.

Page API request
        ↓
