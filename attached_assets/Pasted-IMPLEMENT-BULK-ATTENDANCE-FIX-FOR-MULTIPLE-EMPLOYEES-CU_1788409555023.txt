IMPLEMENT BULK ATTENDANCE FIX FOR MULTIPLE EMPLOYEES

CURRENT PROBLEM

In the Attendance module, each employee currently has an individual "Fix" button.

Example:

Employee | Status | Action
Rafin    | Present | In / Out / Fix
Faisal   | Absent  | In / Out / Fix
Gaf o o r| Absent  | In / Out / Fix
Majeed   | Absent  | In / Out / Fix

Currently, if I need to fix attendance for multiple employees, I have to click "Fix" separately for every employee.

I need a bulk/multiple employee attendance fix feature.

REQUIRED FEATURE

Add a checkbox to every employee row.

Add a "Select All" checkbox in the table header.

Allow selecting:

- One employee
- Multiple employees
- All employees currently shown
- All employees matching the current filters, where appropriate

When one or more employees are selected, show a bulk action toolbar.

Example:

[✓] 5 employees selected

[Bulk Fix Attendance]

The existing individual "Fix" button must remain available.

BULK FIX BUTTON

Add:

"Fix Attendance"

as a bulk action.

The button should appear only when at least one employee is selected.

Example:

☑ Rafin
☑ Faisal

[Fix Attendance]

IMPORTANT:

Do NOT create a separate attendance correction logic.

Reuse the existing individual Fix Attendance functionality and validation.

The bulk operation should apply the same rules to every selected employee.

SUPPORT INDIVIDUAL ATTENDANCE VALUES

The bulk Fix dialog should allow fixing the selected employees' attendance using the existing attendance model.

reuse those existing fields and validation.

IMPORTANT DATABASE REQUIREMENT

Do NOT make hundreds of unnecessary individual frontend requests.

Implement a proper backend bulk endpoint/transaction where practical.

Example concept:

POST /attendance/bulk-fix

with:

{
  employeeIds: [...],
  attendanceDate: "...",
  status: "...",
  inTime: "...",
  outTime: "...",
  notes: "..."
}

The backend must validate every employee before applying the changes.

Use a database transaction.

Either:

ALL selected attendance records succeed

OR

NONE of them are changed.

Do not leave the database half-updated if one employee fails validation.

PERMISSION SECURITY

The bulk Fix action must use the SAME permission rules as the existing individual Fix action.

If a user can individually Fix attendance for an employee, they may bulk Fix that employee.

If a user is NOT authorized to Fix a particular employee:

→ The backend must reject that employee.

Do not rely only on frontend checkboxes.

Respect the existing location-based employee access rules.

- Frozen Hub - Rajaguda
- Tropicane - Kochi

- Head Office

Admin/authorized Head Office users should continue to work according to their existing permissions.
