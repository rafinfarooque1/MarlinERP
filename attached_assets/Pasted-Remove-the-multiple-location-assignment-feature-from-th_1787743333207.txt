Remove the multiple-location assignment feature from the Cash & Bank module completely.

CURRENT ISSUE

In Cash & Bank → Add Account / Edit Account, the form currently shows:

- Available at
- Multiple location checkboxes
- Select All
- Clear All
- Multiple selected locations summary

This is no longer required.

NEW REQUIRED BEHAVIOR

1. ONE CASH/BANK ACCOUNT = ONE LOCATION

Every Cash or Bank account must be assigned to exactly ONE location.

Replace the current multi-location checkbox selector with a simple single-location selector/dropdown.

Example:

Location *

[ Head Office ▼ ]

Available options:

- Head Office
- Frozen Hub - Rajaguda
- Frozen Hub - Calicut
- Tropicane - Kochi
- Tropicane - Ecity

Only one location can be selected.

Remove:

- Multiple checkboxes
- Select All
- Clear All
- "X locations selected"
- Multi-location search/selection UI
- Junction-table-based multi-location assignment from the Cash & Bank UI

2. HEAD OFFICE MUST WORK LIKE A NORMAL LOCATION

Head Office must be available as a single selectable location, exactly like a warehouse.

Examples:

Cash Account A → Head Office

Bank Account B → Frozen Hub - Rajaguda

Cash Account C → Frozen Hub - Calicut

Each account belongs to only one location.

3. LOCATION FILTERING

When a location is selected in the application:

- Show Cash & Bank accounts assigned to that location only.
- Head Office selection shows Head Office Cash & Bank accounts only.
- Warehouse selection shows that warehouse's Cash & Bank accounts only.

When multiple locations are selected at the GLOBAL dashboard/report level:

- Combine the Cash/Bank balances of accounts belonging to the selected locations.
- Do not allow one Cash/Bank account itself to belong to multiple locations.

Example:

Selected locations:

- Head Office
- Frozen Hub - Rajaguda

Dashboard Cash/Bank totals should include accounts from both locations.

But every individual Cash/Bank account must still have only one owner location.

4. ALL LOCATIONS

When "All Locations" is selected globally:

- Include Cash/Bank accounts from all locations.
- Head Office is included.
- Each account must be counted only once.
- No duplicate balances.

5. EXISTING DATA MIGRATION

There is already multi-location account data from the previous implementation.

Safely migrate existing accounts to single-location ownership.

Migration rules:

A. If an account has only one assigned location:
   - Keep that location.

B. If an account has multiple assigned locations:
   - Preserve one canonical location.
   - Prefer the account's existing original location/branch/location_id if available.
   - Otherwise use the earliest/original assignment.
   - Do NOT duplicate the account.
   - Do NOT duplicate balances.
   - Do NOT duplicate ledger entries.
   - Do NOT delete historical transactions.

C. Existing transactions must retain their original transaction/journal location.

Do not rewrite accounting history unnecessarily.

6. DATABASE AND BACKEND CLEANUP

Refactor the Cash & Bank account ownership model so the canonical model is:

cash_bank_account
  → location_type
  → location_id

or the project's existing equivalent single-location fields.

The API should return one location for each account, for example:

{
  id: "...",
  name: "HDFC Bank",
  type: "BANK",
  location: {
    type: "HEAD_OFFICE",
    id: "..."
  }
}

Do not return an array of locations for Cash/Bank account ownership.

Remove or stop using the multi-location assignment relationship for Cash/Bank account availability.

Important:

If the previous junction table is used elsewhere, do not blindly delete it. First verify its usage. Remove only the Cash & Bank dependency on multi-location membership.

Changing the location must be handled safely.

Existing transactions and journal entries must retain their recorded location.

The account's location change should only affect future account availability/filtering unless the existing accounting model safely supports a controlled migration.

Search the entire Cash & Bank module and remove:

- Clear All

- "Available at" multi-location wording
- Any UI that allows one Cash/Bank account to be assigned to multiple locations

IMPORTANT:

Do NOT remove multiple location selection from:

- Business Dashboard

- Global location selector

Head Office + Rajaguda
