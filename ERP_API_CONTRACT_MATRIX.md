## Counts / notable exceptions

- **84/84 source declarations reconciled to the requested-router manifest; no missing or extra route found** in this subset. This is a subset reconciliation, not a claim that the entire 410-route inventory is behaviorally complete.
- Every business route is globally authenticated, but `sales` share-token/PDF and both `storage` routes have **no `requireModuleView/Action` route-local middleware** (`sales.ts:2776,2809`; `storage.ts:44,117`). Storage performs custom employee/attachment-scope checks.
- Explicitly visible period guards cover writes in sales/payments/purchases/returns/stock verification/transfers/production; read/report routes generally have no period lock. Exact guards for every branch of every handler remain **NOT VERIFIED**.
- `GET /stock/reorder-report` visibly lacks the branch `getUserDataScope` predicate used by neighboring inventory reports (`inventory-batches.ts:485-509`): potential scope exception, not behavior inferred beyond source.
- Item-master writes are additionally Head-Office-only (`requireHeadOffice("items")`) for materials, raw materials, items, and assets (`inventory.ts:17-18,150,175,264,286,310,341,364,391,425,461,494,521`); reads do not use that guard.
- Storage placement is intentionally an overlay and does not mutate stock truth/books (`storageLocations.ts:4-16`); BOM writes are master/audit only (`bom.ts:72-78,100-123`).
- Exact frontend callers are sparse because most ERP UI endpoints use generated query/mutation hooks. Only callers listed with file:line were found by literal search; all other caller cells are deliberately **NOT VERIFIED**, not “unused.”
